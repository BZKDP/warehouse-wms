# Бэкапы БД

Основная PostgreSQL-база автоматически копируется во внешнее хранилище GitHub Actions.

## Как это работает

- Workflow: `.github/workflows/database-backup.yml`
- Расписание: ежедневно в 04:15 по Москве
- Хранилище: GitHub Actions Artifacts
- Срок хранения каждой копии: 90 дней
- Формат: PostgreSQL custom dump (`pg_dump --format=custom`)
- Защита: AES-256-CBC + PBKDF2, незашифрованный дамп удаляется до загрузки
- Проверка: перед шифрованием дамп обязательно открывается через `pg_restore --list`

Workflow можно запустить вручную: **GitHub → Actions → Backup PostgreSQL database → Run workflow**.

## Ключ шифрования

Приоритетно используется GitHub Secret `DB_BACKUP_PASSPHRASE`. Если он не задан, workflow использует уже настроенный `SSH_PASSWORD`, поэтому первый бэкап работает без добавления новых секретов.

Для независимости старых копий от смены SSH-пароля рекомендуется один раз задать отдельный постоянный `DB_BACKUP_PASSPHRASE` и сохранить его в менеджере паролей.

## Восстановление

1. Скачать нужный artifact из запуска workflow.
2. Проверить контрольную сумму:

   ```bash
   sha256sum -c sklad-db_YYYY-MM-DD_HH-MM-SS_UTC.dump.enc.sha256
   ```

3. Расшифровать той же фразой, которая использовалась на дату создания:

   ```bash
   openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 \
     -in sklad-db_YYYY-MM-DD_HH-MM-SS_UTC.dump.enc \
     -out sklad-db.dump
   ```

4. Проверить и восстановить в заранее созданную БД:

   ```bash
   pg_restore --list sklad-db.dump
   pg_restore --clean --if-exists --no-owner --no-acl \
     --dbname=ИМЯ_ЦЕЛЕВОЙ_БД sklad-db.dump
   ```

Восстановление поверх рабочей базы выполнять только во время согласованного окна обслуживания.
