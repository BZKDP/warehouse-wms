# GRAсклад Public API

Внешний API позволяет подключать к GRAскладу базу знаний, производственные сервисы, маркетплейсы и внутренние автоматизации без передачи логина администратора.

Актуальная интерактивная документация публикуется самим backend:

- `/sklad/api/public/v1/docs` — документация с поиском, схемами и примерами;
- `/sklad/api/public/v1/openapi.json` — контракт OpenAPI 3.1;
- `/sklad/api/public/v1/status` — публичная проверка доступности.

## Выдача ключа

1. Открыть `Настройки → API`.
2. Нажать «Создать ключ».
3. Указать понятное имя интеграции, срок действия и лимит запросов.
4. Выдать только необходимые права.
5. Скопировать показанный секрет. Повторно посмотреть его нельзя: в БД сохраняется только SHA-256.

Каждой интеграции нужен отдельный ключ. Это позволяет отозвать один доступ, не останавливая остальные сервисы, и точно видеть источник каждой операции.

## Авторизация

Ключ передаётся только в заголовке:

```http
Authorization: Bearer gra_sklad_...
```

Не добавляйте ключ в URL, query string, логи приложения или сообщения об ошибках.

Первый тестовый запрос:

```bash
curl -H "Authorization: Bearer $GRA_SKLAD_TOKEN" \
  http://<SERVER_HOST>/sklad/api/public/v1/me
```

## Права

| Scope | Возможность |
|---|---|
| `products:read` | Список товаров и одна карточка |
| `products:create` | Создание новых позиций |
| `products:update` | Изменение основных полей карточки |
| `products:archive` | Архивирование и восстановление |
| `barcodes:write` | Изменение производственного и других штрихкодов |
| `stock:read` | Сводный остаток и физические размещения |
| `stock:write` | Изменение полей сводного остатка |
| `movements:read` | История перемещений товара |

Метод может требовать несколько scopes. Например, `/products/{article}/stock` требует одновременно `products:read` и `stock:read`.

## Методы

### `GET /products`

Возвращает каталог постранично. Поддерживаются поиск, точный артикул, тип позиции, архив, наличие остатка, дата изменения, сортировка и пагинация.

```bash
curl -H "Authorization: Bearer $GRA_SKLAD_TOKEN" \
  "http://<SERVER_HOST>/sklad/api/public/v1/products?q=астаксантин&limit=50"
```

Поля stock возвращаются только ключам со scope `stock:read`.

### `GET /products/{article}`

Возвращает одну карточку по точному GRA-артикулу. Если в каталоге обнаружены дубликаты артикула, API возвращает HTTP 409 и ID конфликтующих строк, а не выбирает случайную карточку.

### `POST /products`

Создаёт товар. Обязательны `name` и `article`. Артикул должен быть уникальным.

```json
{
  "article": "GRA-12345",
  "name": "Новый товар, 60 капсул",
  "entity_type": "product",
  "production_barcode": "400000009999",
  "barcodes": ["OZN1234567890"],
  "marketplace_barcodes": [
    { "type": "ozon_1", "value": "OZN1234567890" }
  ]
}
```

Для штрихкодов дополнительно нужен `barcodes:write`, для остатков — `stock:write`.

### `PATCH /products/{article}`

Изменяет только переданные поля. Не отправленные значения сохраняются.

```bash
curl -X PATCH \
  -H "Authorization: Bearer $GRA_SKLAD_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"production_barcode":"400000009999"}' \
  http://<SERVER_HOST>/sklad/api/public/v1/products/GRA-12345
```

Если штрихкод уже принадлежит другому товару, возвращается HTTP 409 `barcode_conflict`.

### `DELETE /products/{article}`

Не удаляет строку физически. Карточка получает `archived=true`, а связи и история сохраняются.

Товар с ненулевым сводным или физическим остатком возвращает HTTP 409 `product_has_stock`. Принудительный вызов `?force=true` требует дополнительное право `stock:write` и должен использоваться только после ручной проверки.

### `GET /products/{article}/stock`

Возвращает:

- поля сводного каталога `stock`, `reserve`, `in_transit`, `quantity`;
- фактический итог по размещениям;
- ненулевые места: полки, паллеты, коробки и товар на руках у сотрудников.

### `GET /products/{article}/movements`

Возвращает журнал перемещений от новых к старым: тип операции, количество, откуда, куда, источник изменения, исполнитель, заметка и время.

## Ошибки

Ответы об ошибке имеют единый формат:

```json
{
  "error": "insufficient_scope",
  "message": "У API-ключа недостаточно прав для этой операции",
  "required_scopes": ["barcodes:write"],
  "request_id": "a0f17c2d"
}
```

| HTTP | Значение |
|---|---|
| 400 | Некорректные параметры или тело |
| 401 | Ключ отсутствует, неизвестен, отозван или просрочен |
| 403 | Не хватает scopes |
| 404 | Товар не найден |
| 409 | Конфликт артикула, штрихкода, дубликат или остаток |
| 429 | Превышен лимит запросов |
| 500 | Внутренняя ошибка |

Во всех обращениях к администратору нужно указывать `request_id`.

## Лимиты и журнал

Для каждого ключа задаётся собственный лимит запросов в минуту. Текущее состояние приходит в заголовках:

- `X-RateLimit-Limit`;
- `X-RateLimit-Remaining`;
- `X-RateLimit-Reset`;
- `Retry-After` при HTTP 429.

В `Настройки → API → Журнал операций` сохраняются ключ, метод, операция, путь, статус, длительность, IP, User-Agent, очищенное тело запроса и код ошибки. Заголовки авторизации, пароли, токены и секреты в журнал не записываются.

## Важное различие остатков

Поля `stock`, `reserve`, `in_transit` и `quantity` — сводный снимок карточки. Их может перезаписать следующая синхронизация с МойСклад.

Физические размещения на полках, паллетах и в коробках через Public API v1 доступны только для чтения. Для их изменения должны использоваться штатные операции перемещения GRAсклада, чтобы сохранялись транзакционность, задания, начисления GRA и складской аудит.
